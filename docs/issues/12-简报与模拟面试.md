# 12. 面试前简报 + 错题驱动模拟面试

**类型**：AFK
**依赖**：10 面试复盘与题库、11 项目档案接入
**先读**：`docs/DESIGN.md` 6.2（模拟面试与面试前简报）

## 要构建什么

两个共享题库查询逻辑的功能。

**面试前简报**：选定一条投递，汇总该公司的历史事件、上次被问的题、相关项目档案要点、当前薄弱题目，由 LLM 生成一页考前提纲。

**错题驱动模拟面试**：从题库中挑题进行多轮文字问答，结束后回写自评和掌握状态。

## 优先级

**简报的优先级高于模拟面试，先做简报。**

理由：简报是**刚需时刻**（面试前一小时）的产物，使用频率会远高于需要主动挤出半小时的模拟面试。如果时间有限，做完简报就可以先交付。

## 关键约束

- **数据检索由代码完成后拼入 prompt，不要让 LLM 自己去查数据库**。系统里没有 agent、没有工具调用（见 `DESIGN.md` 第 3 节「关于 Agent」）
- **不做语音**。ASR/TTS 链路的工程量和延迟都是坑，而「练口头表达」是通用能力，用现成产品或找同学对练性价比更高。本系统的不可替代性来自数据，不来自形式
- 模拟面试的出题优先级：**该公司历史真题 > 标记为 `WEAK` 的题 > 项目档案推导出的追问**
- 模拟面试结束必须**回写 `question.selfRating` 和 `status`**，形成闭环。没有回写，这个功能就只是个玩具
- 简报要能**一页看完**，不要生成长篇大论。面试前一小时没人会读三千字
- 无历史数据时要有合理降级：新公司没有历史真题，就只用项目档案和通用薄弱项出题，不要报错或返回空

## 这两个功能的价值来源

它们唯一不可替代的资产是**用户自己的数据**——真实被问过的题、真实答崩的那几道、真实项目的档案、这家公司往年爱问什么。通用的模拟面试满大街都是，随便开个对话模型就能做。所以实现时凡是要在「通用性」和「用上用户自己的数据」之间选择，一律选后者。

另外，这两个功能会反过来激励用户认真做复盘（第 10 片）——复盘质量直接决定这里的输出质量，形成正循环。

## 验收标准

- [ ] 选定一条投递能生成简报，内容包含该公司历史事件、历史题目、相关项目要点、当前薄弱项
- [ ] 简报长度控制在一页以内
- [ ] 模拟面试能按优先级出题、进行多轮问答、结束后给出反馈
- [ ] 模拟面试结束后自评正确回写到题库，题目状态变化在题库页面可见
- [ ] 对没有历史数据的新公司能合理降级
- [ ] 所有数据检索在代码中完成，prompt 中是拼好的上下文
