## 1. 目标

一个 NestJS module，为后续所有 LLM 功能提供统一入口：prompt 模板管理、模型调用、Zod 校验、失败重试、脱敏、调用日志。配一个简单的调试页面，输入文本即可查看结构化输出。

**目标约 200 行，不要过度设计。这是一个薄适配层，不是一个框架。**

---

## 2. 背景

系统内所有 LLM 任务都是**无状态单次调用**：判断邮件是否招聘相关、从邮件抽取字段、公司名归并判断、面试记录结构化、简报生成。没有工具调用循环，没有自主决策。多轮对话（复盘追问、模拟面试）的对话方是用户，本质是维护 message 数组。

唯一真正 agentic 的任务是「读三万行代码写项目档案」，该任务外包给 Cursor（见 JH-11）。

### 成本背景

供参考，说明成本不是约束条件：3000 封邮件经粗筛后约 300-400 封进 LLM，每封取正文前 2000 token，总量约 60 万 token，以 DeepSeek 价格计全量跑一遍成本为个位数人民币。所以不需要为省钱做复杂的缓存或降级设计，**隐私才是真正的约束**。

## 4. 详细规格

### 4.1 模型调用

- 用 OpenAI 官方 SDK，把 `baseURL` 指向 DeepSeek。DeepSeek 和 Qwen 都兼容 OpenAI 协议，**切换供应商只应该改配置，不改代码**
- API key 从环境变量读取，不入库、不写进代码

### 4.2 脱敏中间件

发送前将**手机号、身份证号、银行卡号**替换为占位符。

**公司名、岗位名、薪资不脱敏**——脱了就没法抽取了。

### 4.3 输出校验与重试

- 输出必须用 Zod 校验
- 不合格重试一次
- 仍失败则记录日志并返回失败结果，**不要抛异常中断整批处理**

### 4.4 调用日志

记录每次调用的 prompt 名称、token 数、耗时、成败，便于成本统计和 prompt 迭代时的效果对比。

预留 Langfuse 接入点（可选实现）。邮件抽取的 prompt 会反复迭代，有 trace 记录能量化每次改动的效果。

### 4.5 调试页面

一个简单页面：选择 prompt 模板、输入任意文本、查看结构化输出与原始响应。这是 JH-09 调 prompt 时的主要工作台。

## 6. Acceptance criteria

- [ ] 能用一个测试 prompt 调通 DeepSeek 并返回符合 Zod schema 的结构化 JSON
- [ ] Zod 校验失败时会自动重试一次
- [ ] 重试后仍失败时返回失败结果而非抛异常
- [ ] 脱敏对手机号、身份证号、银行卡号生效，有单元测试覆盖
- [ ] 脱敏不会影响公司名、岗位名的抽取
- [ ] 调用日志可查询，包含 token 数和耗时
- [ ] 通过修改配置能切换到 Qwen，代码无需改动
- [ ] 有一个调试页面可以输入任意文本查看结构化结果

## 7. 验证步骤

```powershell
# 配置 .env（LLM_BASE_URL / LLM_API_KEY / LLM_MODEL），勿提交真实 key
pnpm typecheck
pnpm test    # 脱敏单测必须覆盖手机号/身份证/银行卡

pnpm dev
# 手测清单：
# 1. 调试页输入一段含手机号的文本 —— 日志中发出的 prompt 应已脱敏，公司名保留
# 2. 故意让 prompt 输出不符合 schema 的内容 —— 应重试 1 次后返回失败而非崩溃
# 3. 把 LLM_MODEL 改成 Qwen 的模型名并重启 —— 应正常工作，代码未改
# 4. 查看调用日志 —— 应含 prompt 名称、token 数、耗时、成败
```

---

## 8. 不做

- **引入任何 agent 编排框架**（LangGraph、Mastra 等）。所有任务都是无状态单次调用，引入编排框架是为不存在的复杂度付出真实的复杂度
- 工具调用（tool calling）循环
- 本地模型 / Ollama（8GB 显存不足，见 DESIGN.md 第 10 节）
- 为省成本做复杂缓存或降级（成本是个位数人民币）
- 脱敏公司名、岗位名、薪资
- 具体业务 prompt（邮件抽取属 JH-09，面试结构化属 JH-10）——本片只提供框架 + 一个测试 prompt
