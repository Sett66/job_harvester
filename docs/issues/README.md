# 开发任务索引

本目录下每个文件是一个**可独立开发的垂直切片**。每片都穿透数据库、API、前端、测试所有层，做完即可单独验证，而不是「先把所有表建完」这种横向切法。

## 给接手的 agent

**动手前必读 `docs/DESIGN.md`**，尤其是第 2 节「核心设计原则」——遇到文档没写到的分歧时以那五条裁决。每个任务文档开头会指明还需要读哪几节。

任务文档里的「关键约束」部分是踩过坑或经过讨论才确定的，**不要自作主张改**。如果你认为某条约束有问题，停下来说明理由，不要直接绕过。

## 并行波次

骨架必须先单独完成，之后可以多路并行：

```
第 0 波   01 骨架                         （单独做，人工验收）
第 1 波   02 · 06 · 07 · 11              （四条线互不接触，可同时开工）
第 2 波   03（需 02） · 08（需 07）
第 3 波   04 · 05 · 09 · 10              （四条线可同时开工）
第 4 波   12 · 13
```

最多可同时开四个 agent。同一波次内的任务不接触相同文件，冲突风险低。

## 优先级说明

路线图的唯一标准是「多少天后能第一次真正用上」。**01 → 02 → 03 → 04 是主干**，走完这四片系统就是一个可用的手动版进度追踪器，此时即可投入日常使用。邮件自动化（07 → 08 → 09）是在此基础上的增强，不是前置条件。

反直觉但关键的一点：**手动版必须排在邮件管道之前**。理由见 `DESIGN.md` 第 9 节。
