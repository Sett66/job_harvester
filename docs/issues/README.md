# 开发任务索引

本目录下每个文件是一个**可独立开发的垂直切片**。每片都穿透数据库、API、前端、测试所有层，做完即可单独验证，而不是「先把所有表建完」这种横向切法。

## 给接手的 agent

**动手前必读 [`docs/DESIGN.md`](../DESIGN.md)**，尤其是第 2 节「核心设计原则」——遇到文档没写到的分歧时以那五条裁决。每个任务文档的 §3「前置阅读」会指明还需要读哪几节。

任务文档 §4「详细规格」里的约束是踩过坑或经过讨论才确定的，**不要自作主张改**。如果你认为某条约束有问题，停下来说明理由，不要直接绕过。

每片文档统一采用九章结构：

| 章节 | 用途 |
|---|---|
| §1 目标 | 这片要交付什么 |
| §2 背景 | 为什么这样做，真实数据依据 |
| §3 前置阅读 | 动手前必读的文档与上游产出 |
| §4 详细规格 | 实现细节与**不可绕过的约束** |
| §5 建议改动文件 | 路径与动作，**含「不要改」** |
| §6 Acceptance criteria | 逐条可勾选的验收项 |
| §7 验证步骤 | 可直接执行的 PowerShell 命令与手测清单 |
| §8 不做 | 明确排除的范围（防止 scope creep） |
| §9 交付物 / 下游 | 谁会依赖本片的什么产出 |

§5 的「建议改动文件」是并行开工的关键——**同一波次内的任务应尽量不碰同一个文件**。若发现冲突，先在此索引中登记再动手。

## 并行波次

骨架必须先单独完成，之后可以多路并行：

```
W0   JH-01 骨架                              （单独做，人工验收）
W1   JH-02 · JH-06 · JH-07 · JH-11           （四条线互不接触，可同时开工）
W2   JH-03（需 02） · JH-08（需 07）
W3   JH-04 · JH-05 · JH-09 · JH-10           （四条线可同时开工）
W4   JH-12 · JH-13
```

最多可同时开四个 agent。同一波次内的任务不接触相同文件，冲突风险低。各片声明的改动范围见各自 §5。

## 优先级说明

路线图的唯一标准是「多少天后能第一次真正用上」。**JH-01 → 02 → 03 → 04 是主干**，走完这四片系统就是一个可用的手动版进度追踪器，此时即可投入日常使用。邮件自动化（JH-07 → 08 → 09）是在此基础上的增强，不是前置条件。

反直觉但关键的一点：**手动版必须排在邮件管道之前**。理由见 [`DESIGN.md`](../DESIGN.md) 第 9 节。

另一条高价值路径是 **JH-05 → JH-10 → JH-12**：导入 35 条实习投递与语雀历史真题后，可以在秋招第一场面试之前就产出一份针对性复习清单。这条线不依赖邮件管道。
