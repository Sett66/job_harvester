# 08. 规则粗筛

**类型**：AFK
**依赖**：07 邮箱同步
**先读**：`docs/DESIGN.md` 5.2（识别与抽取）

## 要构建什么

对已入库的邮件用**纯规则**计算 `screenResult`（`IRRELEVANT` / `SUSPECT` / `RELEVANT`），规则可配置，邮件列表页可按此过滤，并显示分类统计。

**本片刻意不接 LLM。**

## 为什么要单独做这一片

目的不只是省钱。更重要的是**先用纯规则跑一遍真实收件箱，观察能捞出多少、漏掉什么**。这个观察结果会直接告诉下一片的 prompt 该怎么写——哪些邮件模板是规则搞不定的、LLM 需要处理什么样的边界情况。跳过这一步直接上 LLM，等于在没有基线的情况下调 prompt。

## 关键约束

- 规则包括：发件人域名白名单、发件人黑名单、主题关键词、正文关键词
- **规则配置放在可编辑的文件或数据库中，不要硬编码**。第 09 片会实现「用户确认后自动把发件人域名加入白名单」，需要这个配置是可写的
- **粗筛必须可重跑**：改了规则后能对全部历史邮件重新计算，不需要重新拉邮箱（见 `DESIGN.md` 第 2 节原则 1）
- **宁可放宽也不要漏**。多标一些 `SUSPECT` 只是多花几分钱 LLM 费用，漏掉的邮件后面没有任何机会补回来
- 页面要显示统计数字（各类各多少封），这是评估规则效果的唯一依据

## 验收标准

- [ ] 能对全部已入库邮件执行粗筛
- [ ] 邮件列表页可按 `screenResult` 过滤
- [ ] 规则可编辑，修改后重跑生效
- [ ] 显示各分类的邮件数量统计
- [ ] 重跑不会丢失或覆盖邮件原始数据
- [ ] 人工抽查若干封 `IRRELEVANT` 的邮件，确认没有误杀招聘邮件
- [ ] 把规则跑在真实收件箱上，记录一份观察结论（捞出多少、明显漏掉哪类），供第 09 片写 prompt 参考
