## 1. 目标

对已入库的邮件用**纯规则**计算 `screenResult`（`IRRELEVANT` / `SUSPECT` / `RELEVANT`），规则可配置，邮件列表页可按此过滤，并显示分类统计。

**本片刻意不接 LLM。**

---

## 2. 背景

单独做这一片的目的不只是省钱。更重要的是**先用纯规则跑一遍真实收件箱，观察能捞出多少、漏掉什么**。这个观察结果会直接告诉 JH-09 的 prompt 该怎么写——哪些邮件模板是规则搞不定的、LLM 需要处理什么样的边界情况。

跳过这一步直接上 LLM，等于在没有基线的情况下调 prompt。

## 4. 详细规格

### 4.1 规则维度

- 发件人域名白名单 → `RELEVANT`
- 发件人黑名单 → `IRRELEVANT`
- **排除关键词**（主题或正文）→ `IRRELEVANT`（如满意度调研、面试反馈，优先于正向词）
- 主题关键词 → `RELEVANT`
- **正文强相关关键词** → `RELEVANT`（如「感谢投递」「收到您的申请」）
- 正文弱相关关键词 → `SUSPECT`
- 以上均未命中 → `SUSPECT`（默认放宽，避免漏掉招聘邮件）

判定优先级：黑名单 > 排除词 > 白名单 > 主题关键词 > 正文强相关 > 正文弱相关 > 默认 `SUSPECT`。

规则文件默认路径：`data/screen-rules.json`（在 `data/` gitignore 内）。首次运行 `rescreen` 会按默认关键词创建该文件。示例见 [`docs/screen-rules.example.json`](../screen-rules.example.json)。

### 4.1.1 实现文件

| 文件                                             | 职责                                            |
| ------------------------------------------------ | ----------------------------------------------- |
| `apps/server/src/modules/mail/screen.service.ts` | 纯函数 `computeScreenResult` + 全量重跑         |
| `apps/server/src/modules/mail/screen-rules.ts`   | 规则读写、`addWhitelistDomain`（供 JH-09 反哺） |
| `apps/server/src/commands/rescreen.ts`           | CLI 全量重跑                                    |
| `GET /api/mails/screen-stats`                    | 分类统计                                        |
| `GET /api/mails?screenResult=`                   | 按分类过滤列表                                  |

### 4.2 关键约束

- **规则配置放在可编辑的文件或数据库中，不要硬编码**。JH-09 会实现「用户确认后自动把发件人域名加入白名单」，需要这个配置是可写的
- **粗筛必须可重跑**：改了规则后能对全部历史邮件重新计算，不需要重新拉邮箱（见 DESIGN.md 第 2 节原则 1）
- **宁可放宽也不要漏**。多标一些 `SUSPECT` 只是多花几分钱 LLM 费用，漏掉的邮件后面没有任何机会补回来
- 页面要显示统计数字（各类各多少封），这是评估规则效果的唯一依据

### 4.3 观察结论产出

本片的交付物不只是代码，还包括一份**观察结论**：在真实收件箱上跑完后，记录捞出多少封、明显漏掉哪类邮件、哪些模板规则搞不定。这份结论是 JH-09 写 prompt 的直接输入，建议落到 `docs/notes/` 或本文件末尾。

```powershell
pnpm typecheck

# 全量粗筛

# 改一条规则后重跑，验证生效且原始数据无损
pnpm --filter server rescreen

pnpm dev
# 手测清单：
# 1. 列表页按 IRRELEVANT / SUSPECT / RELEVANT 分别过滤，统计数字应与列表条数一致

# 3. 对比重跑前后 email 表的 bodyText / bodyHtmlPath —— 应完全未变
# 4. 把观察结论写下来：各类各多少封、漏掉哪类模板
```
