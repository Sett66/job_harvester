# 13. 定时同步 + 打包托盘

**类型**：AFK
**依赖**：07 邮箱同步
**先读**：`docs/DESIGN.md` 5.1（邮件接入）、第 3 节部署形态

## 要构建什么

两件收尾工作：

1. 用 `@nestjs/schedule` 加定时邮件同步
2. 把整个应用打包成可执行文件，启动后自动打开浏览器并挂托盘图标

## 关键约束

**定时同步部分**：

- **复用第 07 片的同步逻辑，不要重写**
- 间隔可配置，默认 15 分钟
- 同步失败不能让进程崩溃，记录错误后等待下次
- **不做 IMAP IDLE**。招聘邮件晚十五分钟看到不影响任何决策，不值得为此维护长连接重连逻辑
- 要能在配置中关闭定时同步（开发调试时需要）

**打包部分**：

- 目标是「双击启动、自动开浏览器、托盘图标可退出」，**不做 Electron 或 Tauri 完整桌面端**。文件操作全部在后端进程完成，不受浏览器沙箱限制，桌面端只多给一个「双击启动」，不值得成倍的工程量
- 前端构建产物由后端托管，**生产环境只有一个进程**
- **`data/` 目录位置要正确**：不能放进打包后的只读目录。应该放在可执行文件同级目录或用户数据目录
- `better-sqlite3` 是原生模块，打包时需要处理原生依赖。这是打包环节最可能出问题的地方
- 打包工具可选 pkg / nexe / Node SEA，选一个能处理原生模块的

## 验收标准

- [ ] 定时同步按配置间隔执行
- [ ] 定时同步可通过配置关闭
- [ ] 同步失败时进程存活，错误被记录，下次照常执行
- [ ] 打包产物双击可运行
- [ ] 启动后自动打开默认浏览器到正确地址
- [ ] 托盘图标存在，可通过它退出程序
- [ ] 打包后数据库和 `data/` 各子目录位置正确，重启后数据仍在
- [ ] 在一台没有安装 Node 的环境下验证打包产物能运行
