## 1. 目标

建立 Turborepo monorepo 骨架，并用「公司管理」这一条最小路径打通所有层，证明技术栈各环节能协同工作。

本片是 tracer bullet：**宁可功能少，也必须端到端贯通**。只做公司的增查，不做投递、不做事件、不做邮件。

---

## 2. 背景

后续 12 片全部依赖本片确立的目录结构、DI 约定和类型贯通方式。骨架里任何一处选错（比如用了 Express adapter、把 Zod schema 放进 server 而非 shared），代价会随片数线性放大。

因此本片是唯一一片**必须人工验收**的基础设施片：验收的重点不是「公司列表能不能显示」，而是「改一个 Zod schema，前后端是否同时报类型错误」。

## 4. 详细规格

### 4.1 端到端路径

必须完整走通，缺一环即未完成：

1. `packages/shared` 中用 Zod 定义 Company 的 schema
2. `apps/server` 用 Drizzle 定义 `company` 表并生成迁移
3. NestJS module 提供 `GET /api/companies` 和 `POST /api/companies`
4. `apps/web` 用 TanStack Query 拉取并展示列表，一个表单可新增
5. 生产模式下 server 托管 web 的构建产物，只有一个进程

### 4.2 目录结构

见 [`docs/DESIGN.md`](../DESIGN.md) 第 3 节。骨架阶段需要建出的最小形态：

```
job_harvester/
├── apps/
│   ├── server/          NestJS + FastifyAdapter + Drizzle + SQLite
│   └── web/             Vite + React + Tailwind + shadcn/ui + TanStack Query
├── packages/
│   └── shared/          Zod schema
├── data/                运行时数据目录（gitignore）
│   └── app.db
└── docs/
```

### 4.3 `company` 表字段

```
id, canonicalName, industry?, website?, note?, createdAt
```

### 4.4 关键约束

- NestJS **必须使用 `FastifyAdapter`**，不用默认的 Express
- Drizzle 没有官方 Nest 集成，需要自己写一个 database provider 把 Drizzle 实例注入到 DI 容器（几十行，社区有现成模式）
- SQLite 驱动用 `better-sqlite3`，同步 API 在本地工具场景下比异步好写
- 数据库文件放 `data/app.db`。**`data/` 目录整体 gitignore**，代码仓库与个人数据严格分离
- 开发时 Vite dev server 把 `/api` 代理到 server
- `packages/shared` 的 Zod schema 必须同时被前后端 import，实现端到端类型贯通。这是整套方案的粘合剂，后续所有切片都依赖它
- 前端用 Tailwind + shadcn/ui，先初始化好，不用堆砌组件

## 6. Acceptance criteria

- [x] 一条命令（如 `pnpm dev`）同时启动前后端
- [x] 浏览器能看到公司列表，能新增公司，刷新后数据仍在
- [x] `pnpm build` 之后以单进程启动，浏览器访问同一端口功能正常
- [x] `data/` 已在 `.gitignore` 中
- [x] `packages/shared` 中的 Zod schema 被前后端共同引用，改动 schema 会让两侧同时产生类型错误
- [x] 有一个集成测试证明 POST 之后 GET 能拿到数据
- [x] README 写明如何启动开发环境和构建

## 7. 验证步骤

```powershell
pnpm install
pnpm --filter shared build
pnpm typecheck
pnpm test

# 开发模式：前后端同时起
pnpm dev
# 浏览器打开 http://localhost:5173 —— 新增一家公司后刷新，数据应仍在

# 生产模式：单进程
pnpm build
pnpm start
# 浏览器打开 http://localhost:3000 —— 同一端口应能访问前端与 /api

# 类型贯通验证：改 packages/shared 里 Company 的某个字段名后
pnpm typecheck   # 预期 server 与 web 两侧同时报错
```

## 8. 不做

- `application` / `event` / `email` / `question` 等任何其他表（JH-02、JH-03、JH-07、JH-10）
- Prisma。**它带 Rust 查询引擎二进制，JH-13 打包成单文件可执行程序时是障碍**
- Express adapter
- 认证、登录、多用户（单人自用，见 DESIGN.md 第 10 节）
- 堆砌 shadcn/ui 组件库，只需初始化可用
- 打包成可执行文件、托盘图标（JH-13）
