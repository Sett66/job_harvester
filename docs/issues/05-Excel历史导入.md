# 05. Excel 历史数据导入

**类型**：AFK
**依赖**：03 事件流与阶段派生
**先读**：`docs/DESIGN.md` 4.1 到 4.4、**附录（真实数据观察）**

## 要构建什么

一次性导入命令，把用户的实习投递 Excel（`E:\24-10-LLH\实习投递.xlsx`，35 条记录）转换成公司、投递、事件三层数据入库。

这批数据不只是历史归档，它是**数据模型的验收测试**——真实数据会暴露模型缺陷，而现在改的成本最低。

## 源数据形态

完整观察见 `DESIGN.md` 附录。核心特征：

```
B1=投递日期  C1=状态  D1=一面        ← 表头只有三列
A11=拼多多 | B11=3.17 | C11=当天测评，29笔试，4.7约面试时间 | D11=4.10一面 | E11=4.14 二面，4.17挂了
                                                                        ↑ E 列有数据但没有表头
A23=腾讯元宝 | C23=捞起来 4.23一面 | E23=4.28二面，4.30挂了   ← 没有投递日期，是被捞的
A16=字节- 抖音搜索 | B16=4.1100000000000003                    ← 浮点误差
```

## 关键约束

- **不能依赖表头**。表头只到 D 列，但 E 列有数据。要按列位置和内容处理
- **一个单元格常含多个事件**，如「当天测评，29笔试，4.7约面试时间」要拆成三条 event。这是因为真实记录粒度本就是事件流，只是被二维表压扁了
- **本片不使用 LLM**。第 06 片可能尚未完成，且 35 条数据量很小。用规则拆解，**无法自动解析的内容保留原文到 `event.rawText` 并标记为待人工确认**，绝不静默丢弃
- 日期形如 `3.11`，无年份，补 **2026**；`4.1100000000000003` 是 Excel 浮点误差，需 round 到 2 位小数
- 公司名如「字节 - 豆包」「字节- 抖音搜索」「字节 -跨境电商」空格位置各不相同，需拆成 `company=字节跳动` + `businessUnit=豆包`，并把原始写法写入 `companyAlias` 表。腾讯同理（腾讯、腾讯元宝、腾讯云智、腾讯视频）
- 无投递日期的行是被捞起的，`channel=被捞`，`appliedAt` 留空，首个事件是 `REVIVED`
- 只有公司名和投递日期、无后续的 16 条，**只导入一条 `APPLY` 事件即可，不要臆造任何后续状态**
- 「简历没过，应该是还在 cd」这类带主观推测的原文必须保留到 `rawText`
- **导入必须幂等**，重复执行不产生重复数据
- Excel 解析不要为此引入重型依赖。xlsx 本质是 zip + XML，标准库即可解析；如需要库，选轻量的

## 验收标准

- [ ] 35 条记录全部导入，无遗漏
- [ ] 字节 3 条、腾讯 4 条分别归到正确的 company + businessUnit，别名已写入 `companyAlias`
- [ ] 拼多多那条的多事件单元格被正确拆成多条 event
- [ ] 腾讯元宝导入后状态正确（被捞 → 一面 → 二面 → 挂）
- [ ] 无后续的 16 条只有 APPLY 事件，状态为「已投递 / 等对方」
- [ ] 无法自动解析的内容进入待确认列表，且原文完整保留
- [ ] 重复执行导入命令不产生重复数据
- [ ] 导入后跑一次全量重算，状态与导入时一致
