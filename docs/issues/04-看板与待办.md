## 1. 目标

系统的主界面，三个部分：

1. **看板**：按「球在谁手里」分栏，最左边一栏永远是需要用户动手的事
2. **今日待办**：真正还没截止的 `ball == ME` 记录，按 `nextDeadlineAt` 排序
3. **沉寂检测**：长期无响应的记录高亮显示

**这是主干的最后一片——走完 JH-01 → 02 → 03 → 04，系统就是一个可日常使用的手动版进度追踪器。**

---

## 2. 背景

真实历史数据中 35 条投递有 16 条属于「投出去之后再无下文」，这是最常见的状态。界面设计要考虑这个分布——不要让沉寂记录淹没了真正在推进的那几条，但也不能让它们完全消失（用户需要定期决定是否手动归档为 `ASSUMED_DEAD`）。

看板之所以按「球在谁手里」而非按环节分栏：一维环节枚举里，「收到笔试通知但没做」和「笔试做完等结果」都是「笔试」，但前者是有截止时间的紧急待办，后者只是等待。按 `ball` 分栏能让「需要我动手」的事永远聚在最左边一栏。

### 2.1 HITL 使用反馈（2026-08-25）

首版按「`ball == ME` 全进今日待办 + 列随内容撑高」做完后，用导入的春招实习数据验收，暴露两处主界面问题：

1. **看板四列和今日待办都是被内容撑开的长列表**，一屏看不到底，不像看板。要改成视口内分区、各容器内部滚动。
2. **已经截止的记录仍出现在「今日待办」**。当前库里 4 条待办（携程/京东测评、腾讯测评、字节豆包面试）截止全在 3 月，今天已是 8 月。今日待办只应留「还没截止」的；过期未闭环的仍留在看板「待我行动」栏，方便补录完成或终止。

同一轮还看到：**字节跳动 · 豆包**时间线已有「流程终止」（原文「2号下午挂了」），当前状态却仍是「面试，待我行动」。这不是看板过滤的 bug，而是 [JH-05](./05-Excel历史导入.md) 把无月份的「2号」解成了 3 月 2 日，排在「3.26 投递」「3.27 约 4.1 一面」之前；派生按 `occurredAt` 顺序，最后一条是面试邀约。本意几乎肯定是 **4 月 2 日挂掉**。本片**不改派生规则**，交叉见 §4.5。

## 4. 详细规格

### 4.1 沉寂检测

**沉寂是算出来的，不是存出来的。** 定义为：

```
ball == THEM && now - lastEventAt > N 天
```

查询时计算，**不落库、不写定时任务去刷新**。存成状态就要维护刷新逻辑，算出来则永远准确（见 DESIGN.md 第 2 节原则 2）。

**`ball == ME` 的记录不参与沉寂检测。** 对「等你行动」的记录报沉寂毫无意义，那是在提醒用户自己拖延。

阈值可配置，默认投递后 21 天、面试完成后 10 天。这两个数字是拍脑袋定的，做成配置项以便实际使用后校准。

### 4.2 今日待办

入选条件（同时满足）：

1. `ball == ME`
2. `stage` 不是 `CLOSED`、不是 `OFFER`
3. **尚未截止**：`nextDeadlineAt` 为空，**或** `nextDeadlineAt` 的**本地日历日 ≥ 今天**

已截止（本地日历日早于今天）的 `ball == ME` 记录 **不进今日待办**，仍出现在看板最左栏「待我行动」。看板卡片对已截止的条目标「已逾期」，避免从今日待办消失后找不到。

比较用**本地日历日**（本机时区，当前使用者为 `Asia/Shanghai`），不用 UTC 日、也不用「时刻是否已过」。同一天即使预约时刻已过，仍留在今日待办——今天下午还要能补录 `INTERVIEW_DONE` / 流程终止。

排序不变：按 `nextDeadlineAt` 排序。**笔试和测评的截止时间优先级最高**——它是唯一一个错过就彻底没机会的时间点，必须排在最前。无截止时间的排在有截止的后面。

过滤与排序都是查询时计算的纯函数，不落库。

### 4.3 布局：视口内分区滚动

主界面按窗口高度铺开，**不要让整页被列表撑成超长滚动条**。结构：

```
┌─────────────────────────────────────────────┐
│ 顶栏（标题 + 全部投递）          shrink-0    │
├──────────────────────┬──────────────────────┤
│ 今日待办             │ 沉寂预警              │  上半区，约剩余视口 40%
│ （内部 overflow 滚） │ （内部 overflow 滚）  │  两列等高
├──────────────────────┴──────────────────────┤
│ 看板四列：待我行动 | 等对方 | Offer | 已结束 │  下半区 flex-1 min-h-0
│ 每列内部 overflow-y-auto，列与列等高         │  吃掉剩余视口
└─────────────────────────────────────────────┘
```

- 根容器：视口高度（`h-screen`），纵向 flex，`overflow-hidden`
- 今日待办 / 沉寂预警：共用同一行高度；各自内容区限高并内部滚动（空状态仍居中显示短文案）
- 看板：吃掉顶栏和上半区之后的全部剩余高度；四列 `flex-1` 且 `min-h-0`；列头固定、卡片列表在列内滚动
- 横向：列过多时仍允许看板区域 `overflow-x-auto`，但竖向不得把页面撑高
- 小屏笔记本上两行都会偏挤，这是可接受的；优先保证「一屏看完结构、列表在盒子里滑」

### 4.4 关键约束

- 看板按公司聚合展示，一家公司下的多条投递归在一起
- 能从看板直接跳转到投递详情
- 能把沉寂记录一键归档为 `CLOSED` + `ASSUMED_DEAD`
- 空状态和数据量大时（50+ 条投递）都要显示合理——数据量大时靠列内滚动，而不是页面无限变长
- 今日待办的过期过滤不得改 `application` 表上的 `stage` / `ball`；过期只影响「今日」列表，不影响派生状态

### 4.5 交叉：时间线有「流程终止」但状态仍是面试

派生规则保持 JH-03 原样：**按 `occurredAt` 顺序折叠事件，最后一条非 `NOTE` 说了算**。时间线里出现 `REJECTED` 并不自动把当前状态打成 `CLOSED`——如果后面还有 `APPLY` / `INTERVIEW_SCHEDULED` 且没有 `REVIVED`，那是导入把日期排错了。

真实案例（导入后的字节跳动 · 豆包）：

| 事件 | 当前错误的 occurredAt | 原文 |
|---|---|---|
| `REJECTED` | 2026-03-02 | 2号下午挂了 |
| `APPLY` | 2026-03-26 | 投递 字节 - 豆包 |
| `INTERVIEW_SCHEDULED` | 2026-03-27 | 3.27 约 4.1一面 |

正确推断应是 4 月 2 日挂掉（继承「4.1 一面」的月份）。修好导入并全量重算后，该条应变 `CLOSED`，从今日待办和「待我行动」栏消失，进入「已结束」。

**本片不要做**：看到时间线有 `REJECTED` 就 sticky 关闭——那会把「挂了之后又投了 / 又约了面试」的后续事件抹掉。修数据归属 [JH-05](./05-Excel历史导入.md)。

## 6. Acceptance criteria

- [ ] 看板按「球在谁手里」分栏，待我行动在最左
- [ ] 今日待办按截止时间正确排序，笔试/测评截止排在最前
- [ ] 今日待办**不含**本地日历日早于今天的记录；这些记录仍在看板「待我行动」栏并标「已逾期」
- [ ] 截止为「今天」的记录即使时刻已过，仍留在今日待办
- [ ] `nextDeadlineAt` 为空的 `ball == ME` 记录仍进今日待办
- [ ] 主界面按视口分区：上半今日待办+沉寂、下半看板；各列表在自己的盒子里滚动，整页不被撑成超长列表
- [ ] 沉寂记录高亮显示，阈值可配置
- [ ] `ball == ME` 的记录不会被标记为沉寂
- [ ] 沉寂状态是查询时计算的，数据库中没有对应的存储字段
- [ ] 能从看板直接跳转到投递详情
- [ ] 能把沉寂记录一键归档为 `CLOSED` + `ASSUMED_DEAD`
- [ ] 空状态和数据量大时（50+ 条投递）都显示合理

## 8. 不做

- 把沉寂状态或「已逾期」落库或用定时任务刷新（违反原则 2）
- 对 `ball == ME` 的记录做沉寂提醒
- 因时间线里出现 `REJECTED` 就强制 `CLOSED`（sticky terminal；修导入见 JH-05）
- 把已逾期记录从看板「待我行动」栏也拿掉（今日待办可以藏，看板必须还能补闭环）
- 日历 `.ics` 导出（见 DESIGN.md 第 10 节）
- 微信推送、系统通知（同上）
- 拖拽改阶段（`dnd-kit` 为可选增强，不在本片验收范围）
- 统计图表（非主干需求）
